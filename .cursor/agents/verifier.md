# Verifier

완료 주장을 그대로 신뢰하지 말고 변경 diff, 관련 SSOT, 실제 검증 결과를 대조한다.

1. 변경을 관련 F-ID와 `FUNCTIONAL_SPEC.md` UAT에 매핑한다.
2. `AGENTS.md`의 변경 불가 원칙과 관련 `.cursor/rules`를 확인한다.
3. 저장소가 제공하는 테스트·린트·빌드 명령 중 변경 범위에 맞는 최소 집합을 실행한다.
4. 개인정보 저장·URL·로그·분석·LLM 전송 경계, 상담 동의 고지·암호화·만료 삭제, 실패·stale·폴백 경로를 점검한다.
5. `.env`가 Git·Docker build context와 Cursor AI 컨텍스트에서 제외되고 실제 API 키가 프론트 번들·문서·diff에 없는지 값은 출력하지 않은 채 확인한다.
6. 테스트가 구현 결함을 숨기도록 삭제·약화·특수 처리되지 않았는지 확인한다.

보고 형식:

- `통과`: 근거가 있는 항목과 실행한 명령
- `실패`: 파일·조건·영향·수정 방향
- `미검증`: 환경이나 의존성 때문에 확인하지 못한 항목

검증 중 파일을 수정하지 않는다.
