# Insurance For All Review Rules

실제 결함, 회귀, 보안·개인정보 위험, 문서화된 수용 기준 위반만 지적한다. 취향이나 근거 없는 리팩터링 제안은 피한다.

## 우선 확인

- 생년월일·성별·지역·보험나이가 PostgreSQL, 영구 브라우저 저장소, URL, 로그, 분석 도구에 남지 않고 P0에서 직업·유병력을 수집하지 않는가
- 프로필이 비영속이어도 개인정보 처리 고지를 제공하고 이를 “개인정보 미수집”으로 잘못 표현하지 않는가
- 개인화 통계가 `POST` JSON body를 사용하며 GET body나 프로필 query parameter를 만들지 않는가
- 원본 PDF·파일명, 원문 생년월일, 세션 프로필, 미마스킹 데이터가 LLM 입력·DB에 포함되지 않는가
- 상담 목적·항목·보유기간·거부권을 고지하고 동의하기 전 연락처를 수집·저장하지 않으며, 저장 시 연락처·메모를 암호화하고 만료 삭제하는가
- 리포트 접근 토큰을 URL·브라우저 저장소에 넣지 않고 `Authorization` 헤더로 받으며, 서버에는 pepper 기반 HMAC만 저장해 상수 시간 비교하는가
- 익명 세션 토큰이 PII를 담지 않는 32바이트 이상 난수이고 안전한 쿠키로만 전달되며 DB에는 별도 pepper 기반 HMAC만 저장되는가
- 실제 `.env`, API 키, 인증 헤더가 Git·Docker 이미지·프론트 번들·로그에 들어가지 않고 `NEXT_PUBLIC_*`로 노출되지 않는가
- 사용자 통계 요청이 공공 OpenAPI를 직접 호출하지 않고 성공한 PostgreSQL 캐시를 사용하는가
- 배치 실패가 기존 active head를 손상하지 않으며 stale 상태를 노출하는가
- 실손 `totalCount`를 가입자 수로, 생명 가입건수를 사람 수로, 집계 보험료를 개인 견적으로 표현하지 않는가
- AI·UI 문구가 가입 권유, 최적 상품, 순위 추천, 화면에 없는 수치를 만들지 않는가
- `apps/web`에 TypeScript 파일·설정·의존성이 추가되지 않는가
- 통계 여정이 메인→`/stats` 허브→사용자 선택 탭이며 스코프 순서를 강제하지 않는가. 「이전」이 허브로 가는가
- 차트가 D3.js(React ref + data join)이며 Recharts/Chart.js로 대체되지 않는가
- 변경된 동작의 정상·오류·경계 테스트가 있고 테스트를 약화해 통과시키지 않았는가

발견 사항에는 영향받는 경로, 재현 조건, 사용자·데이터 영향, 가장 작은 수정 방향을 포함한다.
